FoundU · AI 猎头 Agent 平台全景

一套会随每次人工纠正而变聪明的 AI 猎头操作系统

候选人获取、评估、访谈、客户画像挖掘、匹配推荐、交付跟进——交给多 Agent 系统承载；人只留在访谈和关键决策上。

业务流 数据流 披露引擎 自进化体系 路线图

一、业务流：两条循环，在匹配引擎交汇

人才侧循环负责「把人看准」，企业侧循环负责「把需求挖透」，两条循环的产出在匹配引擎汇合。

访谈护城河：每位候选人最多 3 次访谈机会；访谈本身永远人工，AI 只出大纲和会前简报。

二、数据流：各平台之间怎么流转

人工校正回流——在飞书看板改了 AI 的评分，diff 自动进评估集，宁可多收不可漏收。
对外必经披露引擎——着陆页、微信语料、MCP 返回，统一按「候选人状态 × 信息块层级」裁剪，禁止绕行。

三、披露引擎：一套规则管住所有出口

候选人状态（漏斗阶段）× 信息块层级（语料标签）两轴正交，渐进式披露——让候选人自我筛选，同时完成一次信息交换。

机制规则
置换原则创始人细节是最核心筹码——没投简历就不给，避免对方「拿语料做选择」，信息多的一方占优
尺度规则内置薪酬带宽化（30K → 20-40K）、年龄放宽区间、「高频出差」→「全球飞」
双口径证据链内部含负面扣分细节；候选人侧只见卖点与准备建议

四、自进化体系：三个组件构成闭环

核心思路：不训练模型，进化的是规则、prompt、权重、阈值。每个人工纠正都让系统更聪明一点。

    subgraph S1[评估集 · 自动生长]
        C1[简历评分库]
        C2[访谈打标库]
        C3[语料生成库]
        C4[匹配推荐库]
    end
    subgraph S2[回归闸门 · 改动必过]
        R[改 prompt / 权重 / 阈值
→ 先跑全量评估集
→ AI-人一致率不降才上线]
    end
    subgraph S3[漏斗仪表盘 · 方向盘]
        F[八段漏斗：获取→入库→访谈→85+→推荐→约面→推进→成交
每段两个数字：通过率 + AI-人一致率
周报自动排序「最值得优化的环节」]
    end
    W[运营在飞书看板

    R -->|上线更优版本| W

机制做法
校正即标注每个 AI 产出字段带四元组 ai_value / human_value / corrected_at / corrector——人改一次，评估集多一条
权重版本化匹配权重带版本号，改动必须先过回归才能激活，防止「改一处坏三处」
双回流路径负反馈（拒绝原因）→ 不匹配维度分析反向修正；正反馈（通过者画像）→ 迭代权重与客户画像
冷启动前期权重用人工推荐先验配置——系统第一天就能跑，每跑一次都在积累训练数据
